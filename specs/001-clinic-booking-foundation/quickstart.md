# Quickstart — Clinic Booking Foundation

A runnable walkthrough that proves the feature works end-to-end. Takes under 10 minutes
from a clean clone.

## Prerequisites

- Docker Desktop (or an equivalent Docker + Compose installation).
- The `data/data-pack-01/` directory populated (shipped in this repo).
- A copy of `.env` created from `.env.example`:

```bash
cp .env.example .env
# For Iter 1 you can leave ANTHROPIC_API_KEY blank — LLM features arrive in Iter 2.
```

## 1. Start the stack

```bash
docker compose up --build
```

Expected: backend logs show `Uvicorn running on 0.0.0.0:8000` and the loader printing
`Seed loaded: 5 doctors, 36 schedule rows, N holidays, 25 patients` (first run only).
Frontend logs show `Ready on http://localhost:3000`.

Open:
- Backend docs: <http://localhost:8000/docs>
- Frontend: <http://localhost:3000>

## 2. Smoke the API first (per the brief's "Suggested steps")

In another terminal:

```bash
# Log in as Asha Verma (data pack patient P01)
curl -s http://localhost:8000/login -X POST -H 'content-type: application/json' \
  -d '{"role":"patient","mobile":"9000000001","name":"Asha Verma"}' | tee /tmp/login.json

TOKEN=$(python3 -c "import json;print(json.load(open('/tmp/login.json'))['token'])")

# See doctors
curl -s http://localhost:8000/doctors | python3 -m json.tool

# See Dr. Rao's free slots next Monday
curl -s "http://localhost:8000/slots?doctor_id=1&date=2026-11-16&visit_type=new" \
  -H "Authorization: Bearer $TOKEN" | python3 -m json.tool
```

Expected: `/doctors` shows all 5; `/slots` returns a list of 10-minute-aligned start
times covering 09:00–12:40 and 14:00–17:40 (minus anything already booked).

## 3. Walk the brief's §09 verification table

Each of the 13 rows in `spec.md` User Story 1 maps to one `/appointments` call. Pick a
date in the next two weeks and run each. Representative examples:

```bash
# Row 1 — happy path
curl -s http://localhost:8000/appointments -X POST \
  -H "Authorization: Bearer $TOKEN" -H 'content-type: application/json' \
  -d '{"doctor_id":1,"speciality":"Cataract","visit_type":"new","start_ts":"2026-11-16T10:00:00"}'

# Row 3 — Dr. Rao Thursday AM should refuse with SURGERY_SESSION
curl -s http://localhost:8000/appointments -X POST \
  -H "Authorization: Bearer $TOKEN" -H 'content-type: application/json' \
  -d '{"doctor_id":1,"speciality":"Cataract","visit_type":"new","start_ts":"2026-11-19T10:00:00"}'
```

Expected: happy-path row returns `201`; refusal rows return `409` with a `code` field
matching the acceptance scenario.

## 4. End-to-end in the browser

1. Open <http://localhost:3000>, pick **Patient**, sign in as `9000000001 / Asha Verma`.
2. Go to **Book**, pick Dr. Rao, Cataract, a weekday in the next week, and a slot.
3. Confirm — see it under upcoming appointments.
4. Sign out. Sign in as **Staff**. Open the day's schedule; confirm Asha's booking
   appears.
5. Sign in as **Doctor**, pick Dr. Rao, open the schedule for the booked date, click
   **Mark completed** (after the appointment's start time has passed for the fixed-clock
   variant, or just for demo purposes in dev).
6. Sign back in as Asha; book a **Cataract follow-up** with Dr. Rao → succeeds.
   Try to book a **Cataract follow-up with Dr. Iyer** → refused with
   `FOLLOW_UP_DIFFERENT_DOCTOR`.

## 5. Cross-patient access test (direct API)

```bash
# Note someone else's appointment id (see it in /staff/appointments as Staff)
OTHER_APPT=99
curl -i http://localhost:8000/appointments/$OTHER_APPT/cancel -X POST \
  -H "Authorization: Bearer $TOKEN"
# Expected: 403 with code NOT_YOUR_APPOINTMENT
```

## 6. Optional — the 38-case rule harness

```bash
# Set the fixed clock and run the stretch test suite
CLINIC_NOW=2026-11-02T10:00:00 docker compose exec backend pytest tests/test_rule_harness.py -v
```

Expected: 38 passed.

## 7. Shut down

```bash
docker compose down
# Database state persists in ./data/netracare.db — delete it to re-seed on next up.
```

## What this proves

- The rules engine (`backend/app/rules.py`) refuses every rule-breaking booking with the
  correct `reason_code` (SC-001).
- Patients can only see their own data (SC-002).
- Every refusal carries both a stable code and a UI-displayable message (SC-003).
- A first-time tester can book end-to-end in under 10 minutes (SC-004).
- All three roles can do their core tasks from the browser (SC-005, 006, 007).
